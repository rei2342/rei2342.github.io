## #44「会社を変えても同じ不満が出てきた」

**使用パターン：前提崩壊型**
前提：会社を変えれば不満は消える
崩壊：3社目でも同じ違和感が来た

### 呼び出すイベント（転職ライブラリ）

| 順番 | シーン番号 | イベント名 | 使い方 |
|------|-----------|-----------|--------|
| セットアップ | 転職-14 | 「辞めます」と言った瞬間 | 1社目転職の決意。「これで変わる」という確信を作る |
| セットアップ | 転職-18 | 転職先の前夜 | 期待と不安の混在。高揚感を上げる |
| 転換① | 転職-21 | 入社3ヶ月後、また来た | 核心シーン。「あ、また来た」という感覚の1回目 |
| 転換② | 転職-21（再） | 入社3ヶ月後、また来た | 2社目でも同じ。繰り返しで読者を引きずり込む |
| 結論 | 転職-30 | 自己理解の意味に気づく | 「3社目で初めて分かった」という気づき |

### 感情の流れ

```
決意（「これで変わる」）
↓
高揚（新しい会社への期待）
↓
違和感（3ヶ月後「また来た」）← 1社目
↓
再び決意（「次こそ良い会社を選ぶ」）
↓
また違和感（「また来た」）← 2社目
↓
崩壊（「会社じゃなかった」）
↓
腑に落ちる（自己理解が先だった）
```

### 記事構成

```
① 冒頭フック
  「3社目の入社3ヶ月後にも、同じ違和感が来た。」
  ← 転職-21を冒頭に出す

② 1社目転職の動機と決意
  ← 転職-14（「辞めます」の瞬間）の手前の感情

③ 新しい環境への期待
  ← 転職-18（転職先前夜）、転職-19（入社初日）

④ 3ヶ月後の「また来た」
  ← 転職-21（核心シーン・1回目）
  ここを最初のピークとして膨らませる

⑤ 2社目も同じ流れを短くなぞる
  ← 転職-21（核心シーン・2回目、短縮版）

⑥ 「会社の問題じゃないかもしれない」という疑念
  ← 転職-22（「何が変わったんだろう」）

⑦ 3社目で初めて気づいたこと
  ← 転職-30（自己理解の意味）

⑧ 結論・今
  自己理解を先にする → 転職サービスへの自然な接続
```

### ライブラリ依存度

転職ライブラリ5シーン直接参照。
キャリアライブラリ未作成だが転職ライブラリで代替可能。
▶ **機能する**

## #53「転職は良い会社を選ぶゲームじゃなかった」

**使用パターン：前提崩壊型**
前提：良い会社を選べば解決する
崩壊：自己理解が先だったと気づく

### 呼び出すイベント（転職ライブラリ）

| 順番 | シーン番号 | イベント名 | 使い方 |
|------|-----------|-----------|--------|
| 伏線 | 転職-03 | 職務経歴書で行き詰まる | 「自己PR」欄で何も書けない＝自己理解不足の伏線 |
| 伏線 | 転職-08 | 転職理由を聞かれた瞬間 | 本音が言えない＝自分が何を求めているか分かっていない |
| 伏線 | 転職-28 | 転職理由が人間関係だと言えない | 建前の転職理由＝自己理解の欠如が形になった瞬間 |
| 核心 | 転職-21 | 入社3ヶ月後、また来た | 良い会社に入っても同じ |
| 結論 | 転職-30 | 自己理解の意味に気づく | ゲームのルールが分かった瞬間 |

### 感情の流れ

```
転職活動を始める（良い会社を探すゲームとして）
↓
職務経歴書で止まる（自己PRが書けない）← 伏線①
↓
「転職理由は？」に建前で答える ← 伏線②
↓
良い会社に入れた（ゲームクリアしたはず）
↓
また来た（ゲームクリアのはずが、また同じ）← 前提崩壊
↓
「ゲームのルールが間違っていた」← 気づき
↓
自己理解が先だった ← 結論
```

### 記事構成

```
① 冒頭フック
  「転職先を選ぶことに3ヶ月使った。自分を知ることには1時間も使っていなかった。」

② 職務経歴書で「自己PR」が書けなかった日
  ← 転職-03（伏線として機能）
  「何が得意か分からなかった」

③ 「転職理由は？」に答えられなかった日
  ← 転職-08、転職-28
  本音と建前のズレ＝自己理解不足が形になった瞬間

④ それでも良い会社を選んで転職した
  条件、評判、面接の印象で選んだ事実

⑤ 入社3ヶ月後、また来た
  ← 転職-21（核心シーン）
  「このゲーム、クリアしたはずだったのに」

⑥ 気づき：転職活動の全工程で「自分」を一度も考えていなかった
  ← 転職-30

⑦ 結論
  転職エージェント/キャリア相談への自然な接続
```

### ライブラリ依存度

転職ライブラリ5シーン参照。
#44との差別化ポイント：#44は「3回繰り返す構造」、#53は「伏線を転職活動プロセスに埋める構造」。
▶ **機能する**

## #22「テーマ選定で収益が10倍変わった実験」

**使用パターン：努力無効型**
努力：同じ時間・同じ熱量でガジェットとAI仕事術を発信
無効：努力量ではなくテーマが収益を決めていた

### 呼び出すイベント（副業ライブラリ）

| 順番 | シーン番号 | イベント名 | 使い方 |
|------|-----------|-----------|--------|
| セットアップ | 副業-01 | 同期の副業話を聞いた日 | 副業を始めた動機。読者の共感導入 |
| 努力の証明 | 副業-10 | 1投稿3時間かかる | ガジェット期間の努力量を可視化 |
| 停滞 | 副業-12 | フォロワーが止まった時期 | 努力しているのに伸びない |
| 転換 | 副業-22 | 順番を変えることにした日 | テーマを変えるという決断に変換 |
| 結果 | 副業-29 | 月1万円達成 | テーマ変更後の数字の変化 |

### 感情の流れ

```
副業を始める（ガジェットで）
↓
毎日3時間投稿（努力してる感）
↓
フォロワーが止まる（努力が報われない）
↓
「テーマを変えてみよう」
↓
同じ3時間で全然違う反応
↓
「努力量ではなくテーマだった」← 前提崩壊
↓
テーマを先に評価する設計へ
```

### 記事構成

```
① 冒頭フック
  「同じ1日3時間を使った。テーマを変えただけで収益が10倍になった。」

② ガジェット副業を始めた経緯
  ← 副業-01（動機）の変形
  「AI仕事術より先に、ガジェットを選んでいた理由」

③ 毎日3時間の努力期間
  ← 副業-10（3時間かかる）
  努力量の証明として使う

④ 半年で頭打ちになった数字
  ← 副業-12（フォロワー停滞）
  具体的な数字で壁を示す

⑤ テーマをAI仕事術に変えた
  ← 副業-22（方向転換の決断）
  同じ努力量・同じ時間で始める

⑥ 3ヶ月後の比較データ
  ← 副業-29（月1万達成）の変形
  「同じ努力量で数字が変わった」実験結果

⑦ 結論
  努力量ではなくテーマが収益を決める
  → テーマ評価→アフィリエイト設計への接続
```

### ライブラリ依存度

副業ライブラリ5シーン参照。
ただし「ガジェット vs AI仕事術」という具体的な比較データはcreator_memoryのテーマ選定エントリが必要。
▶ **機能する（creator_memoryとの併用で強くなる）**

## #9「AIはミラーだった」

**使用パターン：努力無効型**
努力：プロンプトを100回磨いた3週間
無効：問題はプロンプトではなく、入力の設計精度だった

### 呼び出すイベント（副業ライブラリ）

| 順番 | シーン番号 | イベント名 | 使い方 |
|------|-----------|-----------|--------|
| セットアップ | 副業-06 | 初投稿作れない | AIを使って何かを作ろうとして止まる（類似構造） |
| 努力の証明 | 副業-10 | 1投稿3時間かかる | プロンプト100回の努力量として転用 |
| 停滞 | 副業-11 | 他アカウントと比較 | 「なぜ自分だけ抽象的な出力が来るのか」という疑念 |
| 転換 | 副業-20 | 「川がなかった」気づき | 「AIが問題ではなく設計が問題」への転換として転用 |
| 結論 | 副業-30 | 設計で動き始める | JSON構造化後の変化として使用 |

### 感情の流れ

```
AIを使って良いコンテンツを作ろうとする
↓
プロンプトを100回磨く（努力）
↓
出力が変わらない、抽象的なまま（停滞）
↓
「プロンプトが悪いのか？」（自問）
↓
「入れているデータが抽象的だから、出力も抽象的」← 気づき
↓
JSON構造化の1日で変わった（小変化大発見）
↓
AIはミラーだった ← 結論
```

### 記事構成

```
① 冒頭フック
  「プロンプトを100回直した。問題はプロンプトじゃなかった。」

② AIで何かを作ろうとした3週間
  ← 副業-06（作れない状態）をAI活用文脈に転用
  「Claudeを使えば良いものができると思っていた」

③ プロンプトを磨き続けた努力
  ← 副業-10（時間がかかる）をプロンプト試行として転用
  「もっと具体的に」「もっと実践的に」100回以上

④ それでも出力が変わらなかった
  ← 副業-11（比較地獄）の変形
  「他の人のAI出力と見比べて、なぜ自分のは抽象的なのか」

⑤ 気づき：入れているものが抽象的だった
  ← 副業-20（川がなかった）の構造を転用
  「AIへの入力設計が、そのままアウトプットに出ていた」

⑥ JSON構造化の1日で変わったこと
  ← 副業-30（設計で動き始める）の変形
  具体的にどう変わったか

⑦ 結論
  AIはミラー / Claude活用設計 → AI tools affiliate接続
```

### ライブラリ依存度

副業ライブラリから感情・構造パターンを5シーン転用。
ただし「プロンプト100回」「JSON構造化」という固有体験はcreator_memoryのAI活用エントリが必要。
副業ライブラリはあくまで「感情の型」として機能する。
▶ **機能する（creator_memoryとの併用必須）**

## 発見したこと

**ライブラリが直接機能した記事：#44、#53**
→ 転職体験は時系列イベントが揃っているため、シーンをそのまま引けた

**ライブラリが「感情の型」として機能した記事：#22、#9**
→ 副業ライブラリのイベント構造（努力→停滞→気づき）は転用できるが、
→ 具体的な数字・固有体験はcreator_memoryが必要
→ ライブラリ = 感情の骨格 / creator_memory = 肉づけ という分業になる

## 結論

```
イベントライブラリの機能 = 確認された

ライブラリの役割：
  感情の型・構造・独り言の素材を提供する
  → 記事のどこにどの感情を置くかの設計図になる

creator_memoryの役割：
  固有の数字・体験・発見を提供する
  → 記事の「俺しか書けない」部分になる

2つが揃った時に初めて
「感情の型 × 一次情報」の記事が生まれる
```

## ★最上位ルール（2026-08-08・他のすべてに優先する）

> **事実台帳で verified になっていない、さくら固有の過去・現在の事実を生成しない。**

記事ごとに別の「さくらの履歴」が生成されていた。TOEICのスコアは5本の記事で
互いに矛盾し（385点・515点・545点・595点・600点が同時に「私のスコア」だった）、
貯金額は15種類あった。個別に禁じても止まらないので、**根拠が無いものを全部止める**。

**対象（最低限）**
- TOEICスコア・受験日・増減
- 貯金・収入・支出
- サービスの登録・契約・無料体験・利用
- 利用期間・回数
- 留学・渡航・居住
- 職歴・仕事内容
- 年齢・期限・将来計画
- 実際の発言・会話
- 第三者から言われた言葉
- 成功・失敗・改善結果
- 固有の日付・場所・人物

**書きたいときは fact ID を付ける**

`playbook/workspace/experience_facts.csv` に `verified=yes` の行を作り、
記事の該当文に付ける。

```html
私はTOEIC600点を取った。<!--fact:F001-->
<span data-fact="F001">私はTOEIC600点を取った。</span>
```

**fact ID が無い、または verified でない場合、生成と公開が失敗する。**
機械は勝手に一般論へ書き換えない。該当文を報告して止める
（`quality_rules.generation_blockers` / `scripts/draft_gate.py`）。
黙って薄めると、何が消えたのか誰も分からなくなるため。

⚠️ **2026-08-08時点で台帳は空。つまり上の11種類は1つも書けない。**
これは想定どおり。実データが登録されるまで、さくらに履歴を持たせない。

**「調べた」「候補に入れた」「公式情報を確認した」も使わない。**
これも一人称の行動で、記事が生成されていることは根拠にならない。
サービスの説明は**サービス側の事実として**書く。

  ×「留学情報館の無料カウンセリングを調べてみた」
  ×「スパトレを候補に入れたのは」
  ○「留学情報館の無料カウンセリングは、公式サイトでは〜となっている」
  ○「第二言語習得論に沿って組まれているのが、スパトレの設計だ」

**公式の料金・仕様・制度には、出典URLと確認日を必ずセットで書く。**
**仮定・試算は「例」「試算」と明記し、個人の実績として書かない。**

## 文章の大前提（2026-08-07・全チャネル共通・最優先）
**誰でも分かる言葉で、読者が自分の場面として思い浮かべられ、共感できるように書く。**
- **読者は賢くない前提で書く。** 正確には、スマホ片手に流し読みしていて、
  推測も逆算もしてくれない。**書いていないことは伝わらない**と考える
  - 行間を読ませない。指示語で受けない（×「そこをやめたら」 ○「予約をやめたら」）
  - 比喩・言い換え・ひねりを使わない。そのままの言葉で言う
  - 1行に1つだけ。**前の行を覚えている前提にしない**
  - 「察してほしい」表現を使わない
- **どの投稿から読み始めても分かるように書く。** スレッドの2投稿目だけが流れてくる人がいる。
  - **1行目で「何の話か」を言う**（×「閉じてた理由は、予約だった」
    ○「オンライン英会話が続かなかった理由は、予約だった」）
  - 前の投稿を読んでいる前提の指示語・省略を使わない
  - **結果はどの投稿にも入れる**。2投稿目だけ読んだ人にも、何がどうなったかが伝わるようにする
- 抽象語（手数・設計・最適化・仕組み・本質）で説明しない。**実際の動作と場面で見せる**
  ×「話し始めるまでの手数が減った」 ○「歯みがきが終わったら、そのままアプリを開いて話す」
- 読者が「それ私だ」と言える具体を必ず入れる。**時間帯・場所・指の動き・心の中の独り言**
  例「仕事から帰って、ご飯作って、やっとスマホを開いたあと」「いつにしよう、って探してるうちに閉じる」
- 専門用語・カタカナの概念語を使わない。中学生が読んで分かる語彙にする
- **説明が2文以上必要になったら、抽象的すぎる合図**。場面に置き換える
- **できるだけシンプルに。** 1つの投稿・1つの段落で言うことを1つに絞る。
  情報を足したくなったら、代わりにどれかを削れないかを先に考える

  （2026-08-05の定説記事で30万円・32万円を日付なしで公開してしまい、後から追記した）
- 本文中の漢数字（二十七歳・二十五万円・三ヶ月など）→ アラビア数字必須（27歳・25万円・3ヶ月）
- **「——」（emダッシュ/二倍ダッシュ）禁止**（AIっぽい）。挿入句は（…）、区切りは読点か句点で表現する

### AIっぽさ排除ルール（2026-08-02・既存53本の実測から策定）
既存記事を計測したら、全記事が同じ語彙と同じ骨格でできていた。**これが最大のAIっぽさ**。以下を厳守する。

| 症状 | 実測 | ルール |
|---|---|---|
| 対比構文の乱用 | 「ではなく」**53/53本・593回** | 「ではなく」「〜のほうだ」は**1記事2回まで** |
| 抽象語の口癖 | 「設計」259回・「構造」153回・「物差し」71回 | 「設計」「構造」「物差し」「本質」は**1記事1回まで** |
| 書き出しの型が1つ | **49/53本**が「〈検索KW〉で検索する人は…」始まり | **検索キーワードのかぎ括弧で書き出さない**。情景・数字・体験の一場面から入る |
| 骨格が2種類だけ | H2が3本か6本のみ／H3が9か18のみ | **H2の本数を固定しない**（4〜7本で内容に応じて変える）。H3も揃えない |
| 共通プロフィールの使い回し | 「4.5万円」**43/53本** | スクール失敗談は**1記事1回まで**。タイトルには使わない |
| 機械的な見出しラベル | 41/53本に「H2-1｜」等 | 見出しに`H2-1｜`のような**採番ラベルを書かない** |

その他:
- 「つまり」「結局」「一行も」「そのものが」も多用しない
- **同じ論法を全記事で使わない**（「上位記事はXと言うが本当はYだ」だけで押し切らない）。
  体験ログ型・比較検証型・失敗告白型・手順型など、記事ごとに骨格を変える

## 記事生成の成果物は3つ（2026-08-09に追加）

新しい記事を作るときは、**必ず3つを別々に出す**。

1. 記事本文
2. Threads投稿文
3. **アイキャッチ画像生成プロンプト** … `workspace/eyecatch-prompts/<記事IDまたはslug>.md`

3つ目は**公開コンテンツではない。画像制作専用の一時データ**。
WordPressの本文・SEOタイトル・メタ・SNS投稿文・公開処理のpayloadへ入れない。
画像の生成 → 反映 → 検証が通ったら削除する。失敗したら削除せず残す。

**アイキャッチが次を全部満たすまで、記事を公開も予約もしない。**
画像生成済み／アップロード済み／featured_media設定済み／alt設定済み／
画像内の文字が本文と一致／未確認の主張なし／サムネイルで読める／
OGPで崩れない／既存記事と判別できる／**文字カード型ではない**

**仮画像を設定して公開するのは禁止。** 画像生成環境が使えないときは
記事を下書きで止めて、プロンプトを残す。文字だけの仮画像を自動生成して
公開・予約しない（`eyecatch_build.py` は既定で反映を止めてある）。

# 第9章 高単価アフィ特有の落とし穴 — 自動化する前に潰す4つ

> 設計が甘いまま自動化すると、間違いを高速で量産するだけになる。先に潰す。
> テク36は `../compliance/` に運用ガードとして切り出し済み（公開前チェックの標準手順）。

---

## 36. Compliance Guard — 薬機法・景表法のチェックを自動化する ★公開前必須

- **使うとき:** 記事を公開する前に必ず。美容/健康/金融/転職などは特に厳格
- **自動化:** 保存時に走らせる方法は `../compliance/README.md`（Hooks案）参照

```
以下の記事を、薬機法・景表法・特定商取引法の3観点で読み、
リスク表現を全て抽出してください。

各表現について
・該当法令
・違反レベル(高/中/低)
・代替表現案
を表で出してください。グレーゾーンも遠慮なく指摘してください。

記事:{{記事本文}}
```

---

## 37. Approval-Rate Optimizer — 承認率を下げない記事構成

- **使うとき:** 公開前。見かけの売上ではなく確定金額を守る

```
以下の記事を、承認率を下げるリスクで5観点評価してください。

①誤クリック誘発の有無
②過剰な誇大表現の有無
③ターゲット外への露出設計
④ABテストの不適切実装
⑤申込前の意図不明な離脱経路

各項目10点満点、合計30点未満なら「公開前修正」と判定してください。

記事:{{記事本文}}
```

---

## 38. ASP Diversification — 1案件依存から脱却する設計

- **使うとき:** 月50万を「12ヶ月安定」させる最大の敵＝1案件依存を点検

```
以下の現在の案件構成を、リスク分散の観点で評価してください。

①各案件の売上依存度
②ASP別の依存度
③ジャンル別の依存度

最も依存度が高い案件が終了した場合の影響額を算出し、
補完候補となる類似案件を5つ提案してください。

現状:{{現在の案件構成と各売上}}
```

---

## 39. Tier Migration Plan — 低単価から高単価へ段階移行する

- **使うとき:** いきなり高単価で結果が出ないとき、3段階で移行

```
以下のペルソナとジャンルで、案件単価帯を
「低(〜3000円)/中(3000-15000円)/高(15000円〜)」の
3段階で移行するロードマップを設計してください。

各段階で
・扱うべき案件タイプ
・必要な記事数
・必要な検証期間
・次の段階に進む判断基準
を表で出してください。

ペルソナ:{{ペルソナ}}
ジャンル:{{ジャンル}}
```

---

### この章のゴール
自動化で間違いを量産する前に、コンプラ・承認率・依存度・単価移行の4つを潰しておく。
テク36（コンプラ）とテク37（承認率）は公開前ゲートとして毎回通すこと。

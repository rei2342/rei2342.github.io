# Threads投稿フォーマット 2026-08-04 改定

人間の推敲で決めた型。ここから反応を見て直していく。

## 決めた形：スレッド3連

| | 役割 | 制約 |
|---|---|---|
| ① | フック | リンクを入れない。最後は「これだけ↓」で次へ送る。120字以内 |
| ② | 中身 | 手順の箇条書き＋読者への翻訳。300字以内 |
| ③ | 導線 | 記事URLだけ（`?utm_source=threads` 付き） |

1投稿目にリンクを入れると表示が伸びないため必ず分ける。

## 文体の規則

- **句点（。）を使わない**。改行が句点の代わり
- 1行は20字前後。読点は1行1個まで。1行に情報を2つ入れない
- 意味のまとまりごとに空行
- 手順は箇条書きで独立させ、数えられる粒度にする（3つ選ぶ／10回／翌朝1回）
- 読者への翻訳を1行入れる（「日本でも同じ」）
- 数字は記事に実在するものだけ。冒頭に3つ並べない
- 最終行は扱った具体の続きを予告する。「noteに書いた」のような固定文言は禁止

## 禁止

対比構文（〜じゃなかった／〜ではなく）、「設計」「構造」「物差し」「本質」、
教訓や説教の締め、感情の演出（泣きそうになった）、emダッシュ、漢数字、
金額表記の混在、ハッシュタグ

## 改定の経緯

旧プロンプトが「句点で静かに区切る」「3行目を『〜じゃなかった』で止める」と
指示していたため、たらたらした対比構文の文章が出ていた。指示そのものが原因。

人間からの指摘を順に反映した:
1. AIっぽい → 対比構文・「設計」・数字3つ並べを特定して除去
2. 暗い → 失敗を語ることと暗く語ることは別。小さくうまくいった瞬間で終える
3. 有益性がない → 「私はこうした」でなく「あなたはこうできる」を入れる
4. 句読点が多い → 句点を廃止し、改行に区切りをさせる
5. 「noteに書いた」が定型 → 内容を予告する形に

## 導線の方針

- **Threads → WordPress 直リンク**（`?utm_source=threads`）
- **X → note**（従来どおり）
- note記事末にはWordPressへの導線があるので、どちらも収益に繋がる
- どちらが読まれるかは utm で後から分けて測れる

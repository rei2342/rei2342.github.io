# Weekly SERP Watcher — 2026-08-31

## 結論: 今回は順位取得を実行できず、①〜④はスキップ。⑥は更新なし

`keywords.csv` の104キーワードについて、このセッション（開発コンテナ）からは
検索順位を取得できなかった。理由は以下の通り、環境的な制約であり、
一時的な取得失敗ではない。**推測値・仮の順位は一切書いていない**
（CLAUDE.md「未取得を0として扱わない」の方針に従う）。

## できなかったこと・理由

1. **順位取得の手段が無い。**
   - `playbook/routines/weekly-serp-watcher.md` の依存欄に「順位は手入力か
     順位取得MCP/API」とある通り、いずれも本セッションには存在しない。
   - `SERPAPI_KEY` / `BING_SEARCH_KEY` は未設定（`playbook/scripts/market_research.py`
     が要求する2つの環境変数）。
   - Search Console 側（`gsc_fetch.py`）も `GSC_SERVICE_ACCOUNT_JSON` 未設定。
   - 開発コンテナは外向きHTTPが遮断されており（`curl` で確認、応答なし）、
     Google検索への直接アクセスも不可能。これは `market_research.py` の
     docstring にも明記されている既知の制約で、同スクリプトは
     GitHub Actions（`market-research.yml` / `rewrite-uploader.yml` の
     `ops:market:<記事ID>`）側でのみ動作する設計になっている。

2. **前週比較がそもそも成立しない。**
   `keywords.csv` の `last_rank` 列は104行**全て空**。過去に一度も
   順位が記録されていないため、今回データが取れたとしても「前週比5位以上
   下落」を計算する基準値が存在しない。このRoutineを本当の意味で走らせる
   には、まず基準値となる初回順位を記録する回が別途必要。

3. **`target_url` も104行全て空。**
   どのキーワードにどの記事URLを紐づけて順位を追うかが未設定。
   順位取得を行う前に、キーワード⇔記事URLの対応付けが要る。

## 実施したこと

- `keywords.csv` の中身と列構成を確認（104件、`last_rank`/`target_url` は空）。
- 順位取得を試みる既存の仕組み（`market_research.py` / `gsc_fetch.py` /
  対応するGitHub Actions ワークフロー）を確認し、必要な環境変数・実行場所を特定。
- `curl` で外向き接続を確認 → 到達不可（想定通り）。
- **`keywords.csv` の `last_rank` / `checked_at` は更新していない。**
  取得していない値を書き込むと「順位が変わっていない／取得済み」と
  誤読される恐れがあるため。

## 次にやること（運営者側の判断が要る）

このRoutineを実際に動かすには、以下のいずれかが必要:

- **A. GitHub Actionsで取る。** `market-research.yml` を実行できる状態にする
  （リポジトリ Secrets に `SERPAPI_KEY` または `BING_SEARCH_KEY` を追加）。
  ただし現状は記事ID単位の取得で、`keywords.csv` の104キーワード一括取得用
  ではないため、スクリプト側の対応も要検討。
- **B. Search Consoleの実測平均順位を代用する。** `GSC_SERVICE_ACCOUNT_JSON`
  をSecretsに追加し `gsc_fetch.py` をActionsで定期実行すれば、実際の掲載順位
  （クエリ別平均順位）が取れる。直近の控えは
  `playbook/workspace/gsc/LATEST.md`（2026-08-23時点、対象期間
  2026-07-24〜2026-08-21）にあるが、これは記事の実クリック/表示ベースで
  `keywords.csv` の104件とは対応が未整理。
- **C. 手入力。** 運営者が実際に検索して `last_rank` を埋め、そこを
  基準値（第1回）としてこのRoutineを翌週から機能させる。

上記いずれかで基準値（初回順位）と `target_url` が揃うまで、
このRoutineは「取得→比較→リライト提案」という本来の役割を果たせない。

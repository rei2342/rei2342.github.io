# Weekly SERP Watcher（テク33）— 2026-09-28 実行結果

**結論: ①〜⑥は実行できなかった。捏造を避けるため、順位データもリライト優先度も出していない。**
`keywords.csv` は一切変更していない（last_rank・checked_at ともに未更新）。

## 依頼されたタスクと、実行できなかった理由

`playbook/routines/weekly-serp-watcher.md` のプロンプトどおり①〜⑥を試みたが、
2つの独立したブロッカーに当たった。どちらか片方が解消しても、もう片方が残る。

### ブロッカー1: 前週比較のベースラインが無い（②が原理的に不可能）

`workspace/keywords.csv`（104行）を確認したところ、**`last_rank` 列は104行すべて空欄**、
`checked_at` は初期投入時の日付（2026-06-05〜2026-08-13、記事生成日の履歴であって順位取得日ではない）。

②は「前週比(last_rank列)で5位以上下落したキーワードを抽出する」だが、
比較対象の前週値が1件も存在しないため、下落幅を計算できない。
④の優先度（下落幅×想定収益）も同じ理由で算出不能。
これは今回の実行環境固有の問題ではなく、**このルーチンが一度も実データで回ったことがない**ため。

### ブロッカー2: このセッションから実際の検索順位を取得する手段が無い（①が不可能）

`playbook/config/content/sakura-content-v1.yaml` の `paths.serp` に明記されている通り、
SERP取得は **「Actions でだけ書く」** と設計されている。実装（`scripts/market_research.py`）を見ると:

- 順位取得には `SERPAPI_KEY` か `BING_SEARCH_KEY` が必須（未設定なら「取得不能」と書く方針。推測で埋めない）
- 本セッション（Claude Code Web/コンテナ）にはどちらの環境変数も**設定されていない**（確認済み）
- ロケールは `ja-JP` / `country=JP` 固定で、モバイル・デスクトップを分けて取る設計。
  本セッションで使える `WebSearch` ツールは **米国限定**（ツール自身の注記どおり）で、
  日本のGoogle検索順位を再現できない
- `market_research.py` はそもそも **記事ID単位**（`workspace/market/serp/<記事ID>.yaml`）で動く設計で、
  `keywords.csv` の `last_rank` 列を更新する処理を持っていない。
  Actionsを回しても、このルーチンが求める「keywords.csvへの反映」は現状では別途つなぎ込みが要る

`CLAUDE.md` 自身の最上位ルールとも整合させた: 「SERP・公式再取得・記事別GA4はこのコンテナから取れないので
『未取得』と書く」「未取得を0として扱わない」「検索順位だけを正解にしない」。
今回、順位を米国ロケールのWebSearchで代用して数字を埋めることもできたが、
それは2026-08-10の市場調査控え（`workspace/market/serp/2026-08-10.yaml`）で一度試して
「これは検索順位ではない」と明記した手法であり、`last_rank`（＝「順位」という名前の列）へ
書き込むと過去にこのプロジェクトが避けようとした誤読を再発させる。そのため見送った。

## やらなかったこと（意図的）

- `keywords.csv` の `last_rank` / `checked_at` の更新 → **していない**。
  取得していないのに更新すると「順位を確認した」という誤った記録が残るため
- 下落キーワードの抽出・見出し構造/文字数/E-E-A-T差分分析・優先度付きリライト候補
  → **前提データが無いので作成していない**（数字を仮置きしていない）

## 解消に必要なもの（次回に向けて）

1. **順位取得の実装**: `.github/workflows/market-research.yml` は存在するが記事ID単位の市場調査用で、
   `keywords.csv` の週次順位トラッキングとは別物。以下のどちらかが要る:
   - `SERPAPI_KEY` または `BING_SEARCH_KEY` を Actions Secrets に設定した上で、
     `keywords.csv` の全キーワードを `ja-JP`/`JP` で取得し `last_rank`/`checked_at` へ書き戻す
     新規スクリプト（Actions専用。このコンテナでは動かせない）
   - もしくは Search Console の実順位（`position`）をキーワード単位で取り込む経路
2. **最低2回分の取得**: ①を初回実行しても、その回はまだ「前週」が無いので②は動かない。
   2回目の取得が終わって初めて②〜④が意味を持つ
3. 上記が整うまで、このルーチン（`weekly-serp-watcher`）は**手動実行しても同じ理由で止まる**。
   スケジュール自体を止めるか、依存が整うまで「未取得」を明示して早期終了する運用に変えるかを検討したい

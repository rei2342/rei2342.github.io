# Threadsの型 — 2026-08-07に確定した版

8/4に決めた型を、8/7に人間が推敲して更新した。
`threads_builder.py` と `daily-article-drafter.yml` のお手本を、この版に差し替えている。

## 何を変えたか

| 変更 | 理由 |
|---|---|
| **リンクを3投稿目 → 2投稿目の末尾へ** | 3枚目まで開く人がほとんどいない。8/5は①1334表示に対し③の反応0 |
| **1投稿目で答えを言い切らない** | 伸びた投稿は冒頭で答えを出していない（支持例1本・仮説） |
| **読点（、）の制限を撤廃** | 「1行1個まで」は締めすぎで、不自然な切れ方になっていた |
| **抽象語をやめて情景で書く** | 「手数が減った」→「歯みがきが終わったら、そのままアプリを開く」 |
| **指示語で受けない** | 「そこをやめたら」は前の行を覚えている前提。読者は覚えていない |
| **どの投稿から読んでも分かるようにする** | 2投稿目だけが流れてくる人がいる。1行目で何の話かを言う |
| **投稿だけで持ち帰れるものを1つ入れる** | 読み逃げされても損をさせない。次も読まれる |
| **締めを「私が何を見て決めたか」型にする** | おすすめではなく判断の共有。宣伝の顔をしない |

## 順番（これを守る）

**1投稿目**
数字を3つ並べる → 何の数字か説明 → 否定で誤解を潰す → 情景 → 結果 → 「↓」で送る

**2投稿目**
1行目で何の話か言う → 情景（独り言） → やめたN個を箇条書き → 代わりにやったこと
→ 結果 → 読者への問いかけ → 読者が今日できること → 「私が何を見て決めたか」で締める

## 書き方の大前提（全チャネル共通・CLAUDE.mdにも記載）

1. 誰でも分かる言葉で、情景が浮かび、共感できるように
2. できるだけシンプルに。足す前に削れないか考える
3. **読者は賢くない前提**。流し読みしていて推測も逆算もしない。書いていないことは伝わらない
4. どの投稿から読み始めても分かるように

## 型が消える事故が起きた

人間のフィードバックに1つずつ対応するうちに、**箇条書きの手順（引き算フレーム）が丸ごと落ちた**。
文単位で直していると、構造が落ちても気づけない。

対策として `threads_builder.py` に機械チェックを入れた。

- 句点が混ざっていないか
- **2投稿目に箇条書きがあるか**
- 28字を超える行が無いか

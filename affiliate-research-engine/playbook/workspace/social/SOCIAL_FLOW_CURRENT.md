**読んで書き起こしただけ。何も動かしていない。**

段は `記事生成 → SNS文生成 → 保存先 → 承認 → 予約 → 投稿 → 成否記録`。

## 1. X — 自動つぶやき（記事とは無関係）

```
（記事生成とは繋がっていない）
      │
      ├─ 1日5スロット cron（07:10 / 12:40 / 19:30 / 22:50 / 00:20 JST）
      │
      ▼
  間隔と確率の判定  ← workspace/x_state.json の next_allowed
      │   64時間経っていなければ skip
      │   経っていても 45% は skip（POST_PROB = 0.55）
      │   next_allowed を20時間超過していたら確率を無視
      ▼
  テーマを決める
      │   60% … 固定8テーマからランダム
      │   40% … drafts/ の**いちばん新しいファイル**のタイトル
      │          ※記事IDもURLも持たない。題名を着想に使うだけ
      ▼
  文体モードを選ぶ（11種からランダム・問いかけ型は2倍の重み）
      ▼
  claude-haiku-4-5 で生成（max_tokens=300）
      ▼
  後処理（emダッシュ除去 / 絵文字前の空白除去 / 128字で文末カット）
      ▼
  ★ 承認なし ─────────────────────────► X へ即投稿（tweepy）
      ▼
  x_state.json を更新（last_post / next_allowed / last_text）
      ▼
  git commit → main へ push
```

| 段 | 中身 |
|---|---|
| 記事生成 | **繋がっていない** |
| SNS文生成 | ワークフロー内に直書きしたプロンプト → claude-haiku-4-5 |
| 保存先 | **保存しない。** 投稿してから `x_state.json` に直近1本だけ残す |
| 承認 | **無し** |
| 予約 | 予約という概念が無い。スロット×確率×間隔 |
| 投稿 | tweepy で即時 |
| 成否記録 | 成功したら state を更新。**失敗したらログに出るだけで残らない。再試行も無い** |

## 2. X — 記事の告知（手動）

```
記事が公開済み
      │
      ▼
  x-promo.yml を手で実行（article_id を渡す）
      │
      ▼
  WordPress から本文を取得
      │   status が publish でなければ**中止**（下書きURLへ飛ばさない）
      ▼
  claude-opus-4-8 で1投稿ぶん生成
      ▼
  後処理（emダッシュ / 絵文字前の空白 / 本文中のURLを落とす）
      ▼
  workspace/x_promo/promo_<記事ID>.md に保存
      │
      ├─ dry_run: true（既定）… ここで終わり。**投稿しない**
      │
      └─ dry_run: false ─► 1投稿目（本文）
                           └─ 返信として2投稿目（URL ?utm_source=x）
      ▼
  x_state.json を更新（自動つぶやきと重ならないよう64時間空ける）
```

| 段 | 中身 |
|---|---|
| 承認 | **`dry_run` を false にすることが承認**。既定は投稿しない |
| 予約 | 無い。実行した瞬間に投稿 |
| 成否記録 | `promo_<記事ID>.md` に本文と文字数。**投稿IDは残さない**。再試行も無い |

## 3. Threads — 記事と同時（3日ごと・主線）

```
daily-article-drafter.yml（3日ごと 05:30 JST）
      │
      ▼
  keywords.csv から todo を1件取る
      ▼
  記事本文を生成 → 品質ゲート → WordPress へ**下書き**投稿
      │   slug から公開URLを組み立てて /tmp/article_url.txt へ
      ▼
  同じドラフトから Threads の2連を生成（claude-haiku-4-5 / max_tokens=800）
      │   ===THREADS_1=== / ===THREADS_2=== / ===NOTE_TITLE===
      │   ===VISUAL=== / ===EYECATCH_* === をまとめて1回で出す
      ▼
  後処理（URL全除去 / ▶行の除去 / 無料体験で終わる行の除去 / 絵文字前の空白）
      ▼
  保存先は2か所
      ├─ workspace/threads/<日付>.md
      └─ WordPress に「【Threads用】<日付>」という**下書き記事**を作る
      ▼
  ★ ここで止まる。**投稿の口が無い**
      ▼
  人が下書きを開いて、コピーして Threads に貼る
      ▼
  成否記録は無し。あとで threads_insights.py が API で表示数を測る
```

| 段 | 中身 |
|---|---|
| 承認 | 人が手で貼るまで出ない＝実質の承認 |
| 予約 | **無い** |
| 投稿 | **人力**。Threadsの投稿用トークンを持っていない |
| 成否記録 | 投稿と文面の対応が**どこにも残らない**。API側は記事IDを知らない |

## 4. Threads — 作り直し（手動・検査つき）

```
threads-builder.yml を手で実行（article_id / memo_id）
      │
      ▼
  WordPress から本文を取得
      │   affiliate_inserter.strip_box() で CTAボックスを外してから渡す
      ▼
  claude-opus-4-8 で2連を生成
      ▼
  clean()（URL除去 / ▶行除去 / 絵文字前の空白）
      ▼
  ★ review() で検査 ── 落ちたら理由を渡して書き直す（最大3回）
      │   句点 / 箇条書きの有無 / 28字超の行 / 抽象語 / 指示語 /
      │   2投稿目の冒頭に話題語があるか / 1投稿目が「↓」で終わるか /
      │   2投稿目が120字以上か
      ▼
  workspace/threads/built_<記事ID>.md に保存
      │   ※ここで **NameError（kuten 未定義）** で落ちる
      ▼
  dry_run: false なら WordPress の【Threads用】メモを更新
      ▼
  人が手で貼る
```

**5経路のうち、出す前に検査しているのはここだけ。**

## 7. 経路をまたいだときに起きること

1. **同じ記事から2〜3本のメモができる。**
   `daily-article-drafter` が日付でメモを作り、`threads_builder` を手で回すと
   記事IDでもう1本できる。実際に 640 と 641 が同じ記事の重複メモになっている。
2. **記事のURLが確定する前にメモができる。**
   記事は下書きで投稿されるので、slug から組み立てたURLは
   公開するまで開けない。メモ584のリンクは**今も開けない**。
3. **記事を書き直しても、メモは古いまま残る。**
   521・526・546・315 は 8月8〜9日に題名と中身を差し替えたが、
   メモとX告知は 8月4〜5日の題名と体験談のままになっている。
4. **止める場所が無い。**
   Xの自動つぶやきだけ、生成した文がそのまま世に出る。
   `experience_facts.csv` の照合も、記事側の品質ゲートも通っていない。
